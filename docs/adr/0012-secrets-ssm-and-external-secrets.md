# ADR-0012: Secrets in SSM Parameter Store with External Secrets

Status: Accepted.

## Context
- The backend and aggregator need the Valkey endpoint and AUTH token, which Terraform creates.
- Secret values must not be committed to git.

## Decision
- Terraform writes `/lab/<env>/valkey/endpoint` (String) and `/lab/<env>/valkey/auth-token` (SecureString).
- External Secrets Operator reads them through `ClusterSecretStore/aws-ssm` with Pod Identity. The role covers only `/lab/<env>/*`.
- The store is usable only from the `lab` namespace.
- `ExternalSecret/lab-valkey` builds `VALKEY_URL` (`rediss://`) and refreshes hourly.
- The Postgres password is generated by CloudNativePG as a Kubernetes Secret and is not in SSM.

## Consequences
- The token is also in Terraform state (private, encrypted bucket). Accepted for the lab.
- Rotation means a Terraform apply, then waiting for the refresh. Pods may need a restart to pick it up.
- No rotation automation is written.
- Add-on Pod Identity roles must match the service account names in the charts.

## Alternatives considered
- AWS Secrets Manager: built-in rotation, billed per secret; price not checked here.
- Secrets in git (SOPS or Sealed Secrets): adds key management.
